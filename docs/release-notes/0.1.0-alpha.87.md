# 0.1.0-alpha.87

**byollm now starts a local model server when a job needs one.** If you have
Ollama installed but not running, byollm will start it and run the job,
instead of the job failing because nothing was listening.

That changes what "off" means. Leaving a server stopped used to be a way of
keeping work off your machine. It is not any more.

What decides it now is your config. A job can only ever name a model you have
configured. Sites cannot pick a model and neither can we. So if there is a
model you do not want running on this machine, the place to keep it out of is
your byollm config, not your server.

One honest limit worth knowing if you run a large model: byollm will start the
server, and it will not check whether the model fits in the memory you have
free.

## Also in this release

- The memory gate asks what a service *costs* rather than reading a declared
  field, so a local model server reached through `openai-http` — the
  documented way to reach one — is checked rather than mistaken for a proxy.
- `tag.sh` refuses to tag a release that has no note in
  `docs/release-notes/`, and the release workflow publishes that note as the
  GitHub release body.
- The release runbook's package counts and setup loops are checked against
  `packages/` instead of proof-read.
