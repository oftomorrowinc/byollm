# 0.1.0-alpha.87

**Your device stops offering a model server that is not running.** Until now,
if you had Ollama installed but stopped, byollm advertised it as available —
and a job routed there reached a port with nothing listening. Now the service
is offered only when something can actually serve it. If you have a local
server you want to share, start it; `byollm status` says which of your
services are running and which are not.

One thing to know: byollm checks memory before it starts a model service. If
available memory is under the limit set on your device, or your system reports
critical memory pressure, the model is not started. Since we do not check
actual model size, set the memory limit on your device to match your largest
model. This does not apply to services that do their compute off-device.

The limit is `minAvailableMemoryBytes` in `~/.byollm/config.json`, and it
defaults to 2 GB. `byollm status` shows the guard, what it read, and the floor
it is using; `byollm log` records every decision with the reading it was made
on.

**A job this device keeps failing to finish is now let go.** After three
attempts on the same job it is refused rather than retried forever, whatever
the reason was.

## Also in this release

- `openai-http` pointed at an address on this machine is treated as a local
  model server, which it is — including for the memory check above.
- A relay stops handing round a job whose payload never arrives, instead of
  offering it to one device after another until it expires. (In
  `@byollm/relay`; a running hub gets it when it takes this version.)
- Releases have notes now, and this file is one: the tag refuses to be made
  without it.
