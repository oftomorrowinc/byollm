# 0.1.0-alpha.88

**byollm now starts a local model server when a job needs one.** If you have
Ollama installed but not running, byollm will start it and run the job,
instead of the job failing because nothing was listening.

That changes what "off" means. Leaving a server stopped used to be a way of
keeping work off your machine. It is not any more.

What decides it now is your config. A job can only ever name a model you have
configured. Sites cannot pick a model and neither can we. So if there is a
model you do not want running on this machine, the place to keep it out of is
your byollm config, not your server.

One thing to know: byollm checks memory before it starts a model service. If
available memory is under the limit set on your device, or your system reports
critical memory pressure, the model is not started. Since we do not check
actual model size, set the memory limit on your device to match your largest
model. This does not apply to services that do their compute off-device.

The limit is `minAvailableMemoryBytes` in `~/.byollm/config.json` and defaults
to 2 GB. `byollm status` shows the guard, what it read, and the floor it is
using.

**A stopped server is offered again, now that something starts it.** In
0.1.0-alpha.87 your device stopped advertising a local server that was not
running, because nothing would have started it. That is no longer true, so the
service is offered again — and the memory check above runs before anything is
started.
