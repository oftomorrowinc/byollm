# 0.1.0-alpha.89

**The largest single message byollm carries is now 6 MB, down from 10.**

This is a wire change. A message over 6 MB is refused, in both directions, by
the relay and by the direct lane alike — the refusal names the size and the
limit, as it did before.

Almost nothing hits it. 6 MB of text is a few thousand pages, so if you are
sending prompts and getting completions back, you will not notice this.

**What it is for is shape, not capacity.** A message this size is the wrong
container for a photo or a video, and the right one is storage with a link to
it — which is how multimodal will work when it arrives. A bigger envelope only
ever postpones that, and in the meantime it makes every relay hold more of
somebody else's memory than it needs to.

There is a second reason, and it is why 6 rather than 8. A hosted byollm
device runs in 320 MB of memory. A 10 MB message buffered inside it is a real
fraction of that, and a device has to be able to hold the largest thing the
network will hand it. **6 is the number at which the smallest device we run can
hold the biggest message we accept.**

## If you are self-hosting

The SDK derives its request limit from the protocol, so updating the package
moves both. If you pinned a body-size limit of your own anywhere in front of
byollm, it is now larger than the one byollm enforces, and yours will never
fire. That is harmless — but it means the sentence your users see comes from
byollm rather than from you.

## Upgrading

```bash
npm install --global byollm@0.1.0-alpha.89
```

Mixed versions are fine in one direction and not the other: an older device
will accept a message this release would refuse. If you run a relay, update it
first.
