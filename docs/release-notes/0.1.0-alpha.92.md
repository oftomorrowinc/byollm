# 0.1.0-alpha.92

**A daemon started by a supervisor no longer waits for an answer nobody can
give.**

This is a one-bug release, and the bug stopped hosted devices working at all
in the ordinary case: set the device up, connect it, then sign in to a CLI
afterwards.

`byollm run` offers to open a sign-in when it finds a service that is
configured but not signed in. That offer is right in a terminal and wrong
everywhere else, and it decided which it was by asking whether its output was
a terminal.

Inside a hosted device it is. The container gives the console a terminal so a
person can type at it, and every process there inherits that answer —
including the daemon, which has nobody typing at it. So it asked, waited, and
ran out of things to do. The process exited, its supervisor restarted it, and
the device sat in that loop instead of serving.

It now takes the answer from the supervisor that started it rather than from a
terminal that belongs to somebody else. On your own machine nothing changes:
`byollm run` in a shell still offers the sign-in, because there is somebody
there to take it.

## If you run a daemon under systemd, launchd or a container

The same fix makes `byollm run` correctly report itself as supervised in those
places. It previously got that backwards wherever a container allocated a
terminal.

## Upgrading

```bash
npm install --global byollm@0.1.0-alpha.92
```

Nothing here is a wire change, and `0.1.0-alpha.91`'s notes still describe
everything else in this line.
