# 0.1.0-alpha.93

**A job that timed out could leave a helper process behind, and the console
protocol arrives.**

## The fix: an escalation that asked the wrong question

Reported privately through [SECURITY.md](../../SECURITY.md) by Rob, whose
report was correct in every particular including the missing test.

When a job runs past its budget, the daemon signals the child's whole process
**group** — because a CLI usually spawns helpers, and killing only the one
process leaves them running. That part has been right for a while.

The escalation after it was not. Two seconds later the daemon sends SIGKILL,
and it decided whether to bother by asking "has the child exited yet?" — a
question about one process, for a signal aimed at a group.

So the case that leaked was the well-behaved one. A CLI that handles SIGTERM
properly exits promptly, the daemon sees it gone, skips the SIGKILL — and any
helper that ignored SIGTERM keeps running, past its job, indefinitely. On a
small machine those accumulate.

The escalation now asks whether anything in the group is still alive, which is
the question the signal was always aimed at.

**If you run `byollm` on a machine with a long-lived daemon, this is worth
taking.** Nothing about it is remotely triggerable — the behaviour belongs to
the CLI being spawned — but the leak is silent and does not clean itself up.

## New: the console session protocol

`@byollm/protocol` gains the frame types for a terminal session carried over
the existing sealed channel: `ConsoleFrame`, `consoleEnvelope`, and
`consoleOrder`.

This is groundwork for browser consoles on hosted devices, and there is
nothing to use yet in this release — no daemon behaviour changes and no new
wire traffic. It is published now because the pieces that will use it live in
other repositories and pin a published protocol.

One property is worth stating, because it is the reason the module exists.
Sealing a stream stops a router **reading** it; it does nothing to stop a
router **reshaping** it. Whoever relays the ciphertext can drop a frame, swap
two, or send one twice, and every frame still decrypts and still verifies —
each one is authenticated on its own and says nothing about its neighbours. On
a terminal that is a truncated command that still runs. So the sequence lives
inside the ciphertext where the relay cannot reach it, and a gap is fatal
rather than tolerated.

## Upgrading

```bash
npm install --global byollm@0.1.0-alpha.93
```

No wire changes. `0.1.0-alpha.91`'s notes still describe the rest of this
