# 0.1.0-alpha.94

**`byollm services manage` now shows you what your CLIs actually serve,
instead of asking you to remember.**

## The prompt that knew the answer and asked anyway

`0.1.0-alpha.91` started asking which model a detected CLI serves, because no
list we maintain can keep up with the names vendors ship. That was right, and
it handed people a question the machine was better placed to answer — the
model was often written down on the same disk.

So it reads what the CLI already knows:

- **codex** keeps its own list of models, with the vendor's own idea of which
  are worth showing and in what order. That list is now the picker.
- **claude** keeps no list, and its own help explains why one is not wanted:
  an alias like `opus` or `sonnet` tracks the latest model, and an alias
  cannot go out of date. So those are offered, with whatever your settings
  already choose shown first.

**Typing a name still works and always will.** The list is a set of
suggestions, never a gate — the whole reason `.91` started asking is that the
model namespace moves faster than our releases, and a list that could *refuse*
a name would put that problem straight back.

Nothing here runs your CLI or spends anything. It reads files that already
exist on your machine, and if they are not there — a fresh install has no
list — you get exactly the prompt you got before.

## Answering the model question now turns the service on

Naming a model is saying yes. Previously you typed a model name and then had
to tick the service on a second screen, which is two answers for one
intention. Now a service whose model you just answered arrives selected.

Skipping still leaves it off entirely, and a CLI whose model we already knew
is unchanged — this is about the question you just answered, not about
switching on everything we find.

## For people building on `@byollm/protocol`

The envelope's format — the exact bytes a signature covers, and the base64url
used around them — is now exported as pure functions with no Node
dependencies, so an implementation running in a browser can share one
definition with the daemon rather than keeping a second copy that can drift.

No wire change. Envelopes produced and opened by `0.1.0-alpha.93` and this
release are byte-identical, which the tests assert directly.

## Upgrading

```bash
npm install --global byollm@0.1.0-alpha.94
```
