# 0.1.0-alpha.95

**A door into the protocol that a browser can walk through.**

## `@byollm/protocol/portable`

If you are building a web front end against this protocol, importing
`@byollm/protocol` has never worked: the package entry reaches `node:crypto`,
so a bundler stops with `Can't resolve 'net'`. That was not a bug in your
build.

There is now a second entry point that a browser can use:

```js
import { envelopeSignedBody, ConsoleFrame } from "@byollm/protocol/portable";
```

It carries the things a browser needs and nothing that needs Node — the exact
bytes an envelope's signature covers, the base64url around them, the public
identity schema, and the console frame types. No key generation, no signing,
no sealing: those are primitives, and a browser brings its own.

**The shared part is the format, not the crypto.** That is the point. An
implementation that signs with libsodium in a tab and one that signs with
`node:crypto` in a daemon can verify each other's envelopes, because both
build the signed bytes from one definition rather than two that agree today.

Nothing about the wire changed. Envelopes from `0.1.0-alpha.94` and this
release are byte-identical.

## Also here

The console session types are exported through that portable entry as well.
They remain **experimental** — see `docs/schema-lock.md`, which is new in this
release and says exactly which surfaces `0.1.0` will lock and which are
deliberately outside it.

One sentence from it is worth repeating, because it surprises people: every
wire shape is `.strict()`, so an unknown field is refused rather than ignored.
**Adding an optional field is therefore a breaking change** for the side that
has not upgraded.

## Upgrading

```bash
npm install --global byollm@0.1.0-alpha.95
```

No wire changes, and nothing you are running needs to change. If you do not
build for a browser, this release adds nothing you will notice.
