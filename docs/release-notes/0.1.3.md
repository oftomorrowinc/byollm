# 0.1.3

**A small release. One clearer line in `byollm status`, and two lists every surface now shares.**

`PROTOCOL_VERSION` is still `2`. A daemon on 0.1.3 talks to a hub or relay on
0.1.0, 0.1.1 or 0.1.2, and the other way round. The wire, the on-disk shapes
and the hub's endpoints are unchanged, and there is no migration to apply.
Upgrade when it suits you.

## What changed

**`byollm status` names the fix when byollm could start a stopped service.**
A service that is not running, and that byollm cannot start, says your device
cannot start it for you: *start it yourself, then it will be offered*. That is
true of a service whose `type` is `openai-http` even when its address is
Ollama's — byollm only starts a server whose type names it. After a reboot, a
model configured exactly that way read "start it yourself", and it looked as if
on-demand start had broken. When the type that would work is one byollm can
start on this machine — the address is local, the server's binary is on your
`PATH` — the line now ends:

```
— or set "type": "ollama" on it in ~/.byollm/config.json and byollm will start it for you
```

`byollm services` already printed that fix; now the screen people actually look
at says it too. Nothing about what is offered or started has changed — only the
words.

**What BYOLLM does not do yet, as one list.** `@byollm/protocol` exports
`NOT_YET`, and the README's Status and byo-llm.com's *What it doesn't do yet*
both render it:

- Tool use
- Access to your local files
- Streaming — a result comes back whole
- Job kinds beyond llm.generate and llm.chat — no embeddings or images yet
- Jobs while your device is offline — your device has to be online for your jobs to run

The kinds entry is built from `JobKind`, so a new kind changes that line
everywhere the day it lands. With it come `NOT_YET_LEDE`, `NOT_YET_TAIL`,
`notYetSentence()` for a paragraph and `notYetLine()` for a list entry, so a
site rendering the list uses the same words. A test fails when the README's or
byo-llm.com's copy disagrees with the export.

**Hand this to your AI.** `@byollm/protocol` also exports `AGENT_PROMPTS`,
with `AGENT_PROMPTS_HEADING` and `AGENT_PROMPTS_LEDE`: three prompts to paste
into whatever you already use — Claude, ChatGPT, Codex, Cursor, a local model —
so it does the setup and stops where a step needs you. *Set up my computer*,
*Add BYOLLM to my site* and *Run my own relay*. They appear at the top of the
README and under the headline on byo-llm.com, whose main button is now *Hand
this to your AI →*. One file, `AGENT-PROMPTS.md`, is the source for all three
copies, and `verify` fails while any of them drifts. A prompt that tells an AI
to run a command that does not exist is worse than no prompt, so each one is
checked: every `byollm` command against the real `byollm --help`, every
docs.byollm.cloud link against the anchors the docs actually have, and every
package against the ones this repository publishes.

**byo-llm.com links the docs.** A *Docs* link in the navigation, the full
integration guide (docs.byollm.cloud/#embed) from the section on adding BYOLLM
to a site, and *How it works, in plain words* (docs.byollm.cloud/#what-is-byollm)
from the section for people bringing their own model.

## What this release does not change

No wire field, no on-disk shape, no hub endpoint, no dependency, no schema.
The new exports are additions; nothing in `@byollm/protocol` was renamed or
removed.

The warning at the top of the README stands: the protocol is version 2 and
settling; the software is early.
