# 0.1.5-beta.1

**A prerelease for the servers that run byollm: site tools and images, ahead of 0.1.5.**

This is published under the npm dist-tag `beta`, never `latest`. `npm install
@byollm/daemon` and every other plain install still get 0.1.4. The beta exists
so that hubs and servers can take the new endpoints before any daemon from
`latest` can use them. If you run a device, wait for 0.1.5.

`PROTOCOL_VERSION` is still `2`.

## What it carries

- **Site tools** (`llm.tools`, byollm_012): a site declares tools, and the model
  on a device calls them. The tools run on the site's servers, never on the
  device. A tool job that runs out of calls still ends `ok`, with
  `stop: "tool-budget"`, so a site can tell a short answer from a complete
  one. That holds for a job that moved to a second device with its calls
  already used: the second device is refused its first call, and the model
  answers from what it has (byollm_012 §8).
- **Images** (`llm.vision` and `llm.image`, byollm_021): up to 20 MiB an image,
  eight in and four out per job, on local and HTTP backends. Images travel by
  reference as encrypted blobs, not inline.
- 0.1.5's two held fixes, described in its note when it ships.

## What is not in it yet

Two tool MUSTs are not settled yet: one still owes the hub's check, and one
has its checks but not yet the record that says so. The beta may carry
them; 0.1.5 may not. If tools have not passed review by
2026-12-01, `llm.tools` comes out before 0.1.5 and ships in the next release
(the cut line, byollm_021 §Rollout R2).

- **`TOOLS_BUDGETED`**: all three tool-call counters are checked. The
  daemon's counter and the context cap are checked in the conformance kit
  and the daemon's suites (C038, C041, C046). The relay's counter (C039) is
  checked in the relay's suite, and the site SDK's (C040) in the server's,
  each seen to fail under its mutation. The MUST's record still lists C039
  and C040 as planned conformance checks, because neither runs in the kit,
  and until that record is settled it holds the stable release.
- **`TOOLS_MATCH_CONSENT`**: the device's half is checked (C035, C036). The
  hub's refusal of an enqueue whose `toolsDigest` does not match the manifest
  of record (C047) is not checked yet.

## If you run a server

- **Supabase adapter: four migrations.** `20261103230000_tool_calls`,
  `20261104010000_tool_charges`, `20261104050000_blob_bucket` (a private
  Storage bucket and the `byollm_blobs` table), and
  `20261104160000_blob_table_grants`.
- **Your own store adapter** needs the blob methods (`putBlob`, `getBlob`,
  `deleteBlob`) and the tool-call methods (`recordToolCall`, `outstandingToolCalls`,
  `answerToolCall`, `chargeToolCall`). When a job's calls are spent,
  `recordToolCall` returns the `budget` refusal and `@byollm/server` sends
  the right answer; nothing more is needed.
- **A server that answers the daemon's tool calls with its own code**, not
  `@byollm/server`'s, must refuse a call on a job whose calls are spent with
  `403 forbidden` and exactly the message `this job has made every tool call
  it is allowed` (`TOOLS_SPENT_MESSAGE` in `@byollm/protocol`). The daemon
  recognises that pair and closes the job `ok` with `stop: "tool-budget"`.
  Any other refusal reads as a site that did not answer.

The full account comes with 0.1.5.
